# M19 Sync And Run Notes 2026-06-09

## Purpose

M19 is an isolated fusion method copied from M16 and modified only inside this folder. It combines:

- Local Patch NCFD from M12-style raw-image patch matching.
- Feature-map Token NCFD from M16-style spatial token matching.
- Global NCFM baseline with `num_freqs=1024`.

## Adaptive Groups Added From Early Signals

Early same-run logs showed the weighted local-patch term was much larger than the weighted feature-token term:

- `M19_lp01_fmt01_tok256`: weighted patch/token ratio about 3.8.
- `M19_lp02_fmt02_tok256`: weighted patch/token ratio about 3.9.
- `M19_lp03_fmt02_tok256`: weighted patch/token ratio about 5.4.

This means equal-looking lambda values do not produce equal branch strength. The next adaptive search lowers patch weight and keeps or increases token weight:

| Group | globalT | localT | local lambda | grid | encoder | blocks | token lambda | token layers | token freqs |

## Code Changes Relative To M16

- `scripts/run_medmnist_formal_pipeline.py`
  - Defines the M19 fusion groups above.
  - Adds adaptive low-patch groups after observing patch-dominated early loss ratios.
  - Adds `--groups` so each worker can run one selected group.
- `condenser/Condenser.py`
  - Adds M19 fusion loss logging names.
- `utils/utils.py`
  - Adds `_M19` output suffix.

## Launch Policy

The main remote screens run queued groups sequentially. The adaptive controller allows up to three same-project jobs per GPU to get low-patch signals earlier while keeping memory usage well below the 24 GB limit. It does not kill or interrupt existing screens.
